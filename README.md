# Record

Особистий трекер рекордів: підтягування, відтискання, бруси, біг. Виглядає як WorkoutTitan, працює як Record (`netherm3-coder/-record`), дані зберігає на телефоні.

Стан: готові етапи 0–5 з 9: запис результатів, журнал, п'єдестал із цілями, вага й заміри, спортивний статус, досягнення, власні вправи, лічильники стажу й тверезості, вигляд табору з предметами за досягнення, резервна копія у файл, перенесення записів із файла Record. Одиниці й покупки попереду. План і рішення: [docs/plan.md](docs/plan.md). Модель, формули і відмінності від Record: [docs/domain.md](docs/domain.md). База даних: [docs/database.md](docs/database.md). Косметика: [docs/cosmetics.md](docs/cosmetics.md). Резервна копія: [docs/backup.md](docs/backup.md). Перенесення з Record: [docs/record-import.md](docs/record-import.md).

## Запуск

```bash
npm install
npm start
```

Далі відкрий проєкт в Expo Go. Усе, що є зараз, працює в Expo Go без збірки.

Збірка APK:

```bash
EAS_SKIP_AUTO_FINGERPRINT=1 eas build -p android --profile preview
```

## Перевірка

```bash
npm run check    # типи, лінтер без попереджень, тести
npm run bundle   # збирання Android-бандла, ловить помилки імпорту
```

Тести бази даних працюють на SQLite, вбудованому в Node, тому потрібен Node 22.13 або новіший. Node вважає цей модуль експериментальним; `npm test` приховує його попередження про це.

## Перегляд у браузері

Потрібен лише для розробки: так робляться знімки екранів без телефона. Пакети для нього не входять у залежності, щоб не ставити зайвого на телефон.

```bash
npm install --no-save react-native-web@~0.21.4 @expo/metro-runtime@~58.0.17 sql.js@~1.16.0
node scripts/expo-cli.cjs export --platform web --output-dir dist-web
```

Теку `dist-web` віддає будь-який статичний сервер, який на невідомий шлях повертає `index.html`. База в браузері живе в пам'яті й порожня після перезавантаження сторінки.

## Структура

| Тека | Що там |
| --- | --- |
| `src/app` | Екрани. Назва файлу є адресою екрана (expo-router) |
| `src/components` | Спільні компоненти: `Screen`, `Card`, `AppText`, `TabBar` |
| `src/theme` | Скіни: кольори, шрифти, розміри |
| `src/i18n` | Переклади українською та англійською |
| `src/settings` | Збережені налаштування |
| `src/domain` | Правила Record: результат, індекс, п'єдестал, статус, досягнення, перенесення старих записів |
| `src/db` | База даних на телефоні: схема, міграції, читання й запис |
| `src/records` | Історія в пам'яті для екранів і форма результату |
| `src/format` | Текст для чисел, днів і результатів двома мовами |
| `src/backup` | Резервна копія і перенесення з Record: формати файлів і те, як файл виходить із застосунку та заходить назад |
| `src/cosmetics` | Сцена табору: шари, картинки предметів, вибір вигляду |
| `src/premium` | Чи є підписка. До етапу покупок відповідь завжди «ні» |
| `assets/scene` | Арт сцени, який іде в збірку. Його пише `scripts/build-scene-art.py` з оригіналів у `assets/AppAssets` |
| `legacy` | Копія розрахунків Record для тестів. У застосунок не входить |

## Як додати скін

1. Додай ідентифікатор у `THEME_IDS` у `src/theme/types.ts`.
2. Опиши скін у `src/theme/themes.ts` і додай його в `registry`.
3. Додай назву й опис у `themes.<id>` в обох файлах `src/i18n/locales`.

Тести самі перевірять контраст тексту на кожній поверхні і наявність перекладів.

Екрани не задають кольори напряму. Текст виводиться через `AppText`, поверхні через `Card`: вони беруть кольори з поточного скіна.

## Як додати рядок

Додай ключ в `uk.json` і `en.json`. Виклик `t('ключ')` із неіснуючим ключем не пройде перевірку типів, а тест не пропустить ключ, якого немає в одній із мов.
