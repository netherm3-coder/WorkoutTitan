# Record

Особистий трекер рекордів: підтягування, відтискання, бруси, біг. Виглядає як WorkoutTitan, працює як Record (`netherm3-coder/-record`), дані зберігає на телефоні.

Стан: усі дев'ять етапів зроблені з боку коду, лишилися перевірка на телефоні й подача в Google Play ([docs/release.md](docs/release.md)). Є запис результатів, журнал, п'єдестал із цілями, вага й заміри зі своїми частинами тіла, спортивний статус, досягнення, власні вправи з редагуванням, лічильники стажу й тверезості, вигляд табору з предметами за досягнення і повідомленням про нові, резервна копія у файл, перенесення записів із файла Record, кілограми або фунти, сантиметри або дюйми, підписка на преміум-набір і донати через Google Play. План і рішення: [docs/plan.md](docs/plan.md). Модель, формули і відмінності від Record: [docs/domain.md](docs/domain.md). База даних: [docs/database.md](docs/database.md). Косметика: [docs/cosmetics.md](docs/cosmetics.md). Резервна копія: [docs/backup.md](docs/backup.md). Перенесення з Record: [docs/record-import.md](docs/record-import.md). Одиниці: [docs/units.md](docs/units.md). Покупки: [docs/purchases.md](docs/purchases.md). Реліз: [docs/release.md](docs/release.md).

## Запуск

Перший раз, у Termux на телефоні:

```bash
cd ~
git clone -b claude/record-merge https://github.com/netherm3-coder/WorkoutTitan.git
cd WorkoutTitan
npm install
npm start
```

Клон важить близько 100 МБ, разом із `node_modules` на диску піде близько 2 ГБ. Клонуй у домашню теку Termux, а не в спільне сховище телефона: там не працюють символьні посилання, і `npm install` падає.

Наступні рази:

```bash
cd ~/WorkoutTitan && git pull && npm install && npm start
```

Коли Termux покаже адресу `exp://…`, відкрий Expo Go → Enter URL manually → `exp://127.0.0.1:8081`. Ця адреса працює й без Wi-Fi. Перше відкриття збирає бандл на телефоні кілька хвилин. Щоб Android не приспав Termux, поки ти в Expo Go, перед `npm start` виконай `termux-wake-lock`.

Усе, крім покупок, працює в Expo Go без збірки. Покупки працюють лише в застосунку, встановленому з Google Play: [docs/purchases.md](docs/purchases.md).

### APK на телефон

Після кожного надсилання в гілку GitHub сам збирає APK і кладе його на сторінку «Тестова збірка Record». Посилання на файл не змінюється: <https://github.com/netherm3-coder/WorkoutTitan/releases/download/test-apk/record.apk>. Відкрий його на телефоні, дозволь браузеру встановлювати застосунки і встанови. Нова збірка ставиться поверх старої, дані лишаються.

Ця збірка лише для перевірки: вона підписана ключем для налагодження, працює лише на процесорах arm64-v8a, покупок у ній немає. Застосунок із Google Play матиме інший підпис, тож перед ним цю збірку доведеться видалити, а дані перенести резервною копією. Як збирається: `.github/workflows/apk.yml`.

Збірка APK:

```bash
EAS_SKIP_AUTO_FINGERPRINT=1 eas build -p android --profile preview
```

`eas build` вивантажує на сервер EAS лише те, що потрібне для збірки: без оригіналів арту, сторінки магазину й копії Git (`.easignore`). Архів важить близько 11 МБ, а не 240.

## Перевірка

```bash
npm run check    # типи, лінтер без попереджень, тести
npm run bundle   # збирання Android-бандла, ловить помилки імпорту
```

Тести бази даних працюють на SQLite, вбудованому в Node, тому потрібен Node 22.13 або новіший. Node вважає цей модуль експериментальним; `npm test` приховує його попередження про це.

Те саме, і тести ще у двох часових поясах, GitHub запускає сам після кожного надсилання в репозиторій: `.github/workflows/check.yml`. Результат видно біля коміту, галочка або хрестик; подробиці у вкладці Actions.

## Перегляд у браузері

Потрібен лише для розробки: так робляться знімки екранів без телефона. Пакети для нього не входять у залежності, щоб не ставити зайвого на телефон.

```bash
npm install --no-save react-native-web@~0.21.4 @expo/metro-runtime@~58.0.17 sql.js@~1.16.0
node scripts/expo-cli.cjs export --platform web --output-dir dist-web
```

Теку `dist-web` віддає будь-який статичний сервер, який на невідомий шлях повертає `index.html`. База в браузері живе в пам'яті й порожня після перезавантаження сторінки.

## Структура

| Тека | Що там |
| --- | --- |
| `src/app` | Екрани. Назва файлу є адресою екрана (expo-router) |
| `src/components` | Спільні компоненти: `Screen`, `Card`, `AppText`, `TabBar` |
| `src/theme` | Скіни: кольори, шрифти, розміри |
| `src/i18n` | Переклади українською та англійською |
| `src/settings` | Збережені налаштування і посилання на політику приватності |
| `src/domain` | Правила Record: результат, індекс, п'єдестал, статус, досягнення, перенесення старих записів |
| `src/db` | База даних на телефоні: схема, міграції, читання й запис |
| `src/records` | Історія в пам'яті для екранів і форма результату |
| `src/format` | Текст для чисел, днів і результатів двома мовами, одиниці ваги й довжини |
| `src/backup` | Резервна копія і перенесення з Record: формати файлів і те, як файл виходить із застосунку та заходить назад |
| `src/cosmetics` | Сцена табору: шари, картинки предметів, вибір вигляду |
| `src/purchases` | Покупки: підписка й донати через Google Play, чи відкритий преміум |
| `assets/scene` | Арт сцени, який іде в збірку. Його пише `scripts/build-scene-art.py` з оригіналів у `assets/AppAssets` |
| `assets/images` | Іконка і заставка. Їх пише `scripts/build-icons.py` з багаття в `assets/AppAssets` |
| `store` | Сторінка в Google Play: тексти, іконка 512×512, скріншоти, банер і вигадана історія, з якої їх знято |
| `docs/privacy` | Політика приватності, яку публікує GitHub Pages |
| `legacy` | Копія розрахунків Record для тестів. У застосунок не входить |
| `.github/workflows` | Перевірка на GitHub після кожного надсилання |

## Як додати скін

1. Додай ідентифікатор у `THEME_IDS` у `src/theme/types.ts`.
2. Опиши скін у `src/theme/themes.ts` і додай його в `registry`.
3. Додай назву й опис у `themes.<id>` в обох файлах `src/i18n/locales`.

Тести самі перевірять контраст тексту на кожній поверхні і наявність перекладів.

Екрани не задають кольори напряму. Текст виводиться через `AppText`, поверхні через `Card`: вони беруть кольори з поточного скіна.

## Як додати рядок

Додай ключ в `uk.json` і `en.json`. Виклик `t('ключ')` із неіснуючим ключем не пройде перевірку типів, а тест не пропустить ключ, якого немає в одній із мов.
