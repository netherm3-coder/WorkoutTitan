# Резервна копія

Екран «Резервна копія» в налаштуваннях зберігає все внесене в один файл і повертає з файлу. Це ж спосіб перенести дані з Expo Go в окрему збірку або на інший телефон.

## Що у файлі

Файл це JSON з назвою на кшталт `record-backup-2026-11-13.json`.

| Розділ | Що там |
| --- | --- |
| `format`, `version` | `record-backup` і номер формату, зараз 1 |
| `exportedAt`, `appVersion` | Коли і якою версією зроблено |
| `exercises` | Свої вправи. Вбудованих немає: вони є в кожній версії |
| `entries` | Усі результати, з нотатками й посиланнями |
| `bodyWeights`, `bodyMeasurements` | Вага і заміри |
| `bodyParts` | Свої частини тіла: `id` і назва |
| `goals` | Цілі |
| `profile` | Зріст і дати лічильників |
| `look` | Вигляд табору |

У файл іде те, що людина бачить. Не йде: мова, скін і одиниці (це вибір для телефона), усе видалене, записи видаленої вправи й заміри видаленої своєї частини тіла.

Одиниці ті самі, що в базі: кілограми, метри, мілісекунди.

## Читання

Файл береться цілком або не береться зовсім. Якщо хоч один рядок не має сенсу, файл пошкоджений або правлений руками, і половина історії гірша за чесну відмову. Перевіряється кожен запис тією ж функцією, що й у формі запису.

| Відмова | Коли |
| --- | --- |
| не схожий на копію | це не JSON |
| дані, але не копія | JSON без позначки `record-backup` |
| новіша версія | `version` більша, ніж знає застосунок |
| пошкоджений | щось не має сенсу; показується місце, наприклад `entries[12].date` |

М'якше читаються дві речі: розділ, якого немає, вважається порожнім, а предмет вигляду, якого ця версія не знає, замінюється стартовим.

Розділ `bodyParts` з'явився без зміни номера формату: старіша версія застосунку його просто пропустить, а файл без нього читається як файл без своїх частин тіла. Замір частини, якої файл не описує (файл, написаний руками), отримує свою частину з назвою, як у файлі.

## Відновлення

Перед змінами екран показує, що у файлі і скільки записів нові для цього телефона. Нічого не змінюється, доки людина не натисне «Додати дані з файлу».

Відновлення додає, а не замінює:

- нічого з телефона не видаляється;
- якщо те саме є і там, і там (запис із тим самим id, вага за той самий день, ціль для тієї самої дисципліни), лишається версія з файлу;
- видалене після створення копії повертається;
- порожнє поле профілю у файлі не стирає заповнене на телефоні;
- усе відбувається однією транзакцією: помилка посередині лишає телефон як був.

Повторне відновлення з того самого файлу нічого не змінює.

## Як файл виходить і заходить

На телефоні файл пишеться в кеш застосунку і віддається системному меню «Поділитися» (`expo-sharing`); звідти його можна зберегти у «Файли», на Диск або надіслати собі. Назад він заходить через системний вибір файлу (`expo-document-picker`). У браузерному перегляді це завантаження і звичайний діалог вибору.

Вибір файлу не фільтрує за типом: Android часто позначає `.json` як текст або невідомий тип, і фільтр зробив би копію недоступною.

## Що перевірено

- Формат: файл читається назад рівно таким, яким записаний; 26 видів пошкодження відхиляються з правильним місцем.
- База: історія з 400 записів, перенесена з Record, проходить через файл на порожній телефон без змін; злиття, повернення видаленого, відкат при помилці.
- Екран: тести з підміненими файловими функціями.
- Браузер: справжнє збереження файлу, перезавантаження сторінки (база порожня) і відновлення з цього файлу.

## Що не перевірено

Нативна частина на телефоні: меню «Поділитися» і вибір файлу в Expo Go на Android. Тести й браузер її не зачіпають.
